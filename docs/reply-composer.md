# 回复逻辑对照与验证

核对日期：2026-10-23。参考本机 `D:/Project/One/jadx_out/sources` 的反编译产物，仅借鉴目标、草稿和提交语义，界面继续使用 Matter 的底部输入面板。

## One 中可确认的行为

- `app/unique/one/ui/widget/emoticon/EmoticonPicker.java` 定义最近、微博表情、Emoji、其他表情入口；`fx3.java` 的 `weibo` / `emoji` / `custom` 分支分别生成内容。其他表情还可叠加网络下载包，初始离线目录采用 APK 随包资源；在线目录现已另行接入。
- `defpackage/dge.java` 的 `oO0OooO0` 按是否回复评论选择 `comments/create` 或 `comments/reply`。
- `defpackage/dra.java` 的 `oO0OO00` 从草稿附件读取微博 `id`；回复评论时另带 `cid`，正文独立传递，不靠在文本前拼接 `@用户` 确定目标。
- 同一流程还处理媒体上传、验证码和 `rt` 同步转发。它们依赖 One 的客户端协议、账号凭据及上传链路，不能直接把字段搬到 Matter 的移动网页版接口。

## Matter 本次实现

- 评论微博与回复评论共用现有面板。一级评论和楼中楼点击传入实际评论 ID，同时保留一级评论 ID，用于将结果放进正确的回复列表。
- `ReplyRepository` 负责固定账号凭据、登录检查及发布结果映射；ViewModel 经仓库提交，新增写入路径不直接访问 API。
- 草稿按回复目标分别保留在当前导航条目的 ViewModel 内；收起不丢失，离开条目或切账号清理。未实现进程退出后的草稿持久化。
- 同时只提交一条回复。失败保留输入并在面板显示原因；成功只清除对应的未修改草稿，期间编辑或切换目标不会误删新输入。
- 评论列表请求记录发起时已完成的写入：写入前发出的旧响应保留新评论，写入后发起的刷新以服务端结果为准。
- 回复列表分页合并时读取最新状态，避免把发送期间新增的回复覆盖；整体刷新使旧分页请求身份失效。
- 切账号取消发送、推进请求身份并清空草稿；迟到的成功、失败和 finally 不得修改新会话。
- 表情、@ 和话题在光标或选区处插入；输入限制避免截断 emoji 的 UTF-16 代理对，并限制输入区域可见行数。

## 回复工具栏

- 图片按钮使用 Android 系统 `PickVisualMedia(ImageOnly)`，评论附图为单张，支持预览、更换和移除。平台 `AndroidReplyImageReader` 在 IO 线程读取授权内容，限制 20 MB，并将不直接支持的图片格式转换为 JPEG；业务状态只持有平台句柄。
- 选择图片不会立即上传；发布时读取并上传。上传采用网页评论图片协议的原始 bytes、`ent=miniblog`、`ori=1` 和 CRC32 参数。附图评论走网页 `ajax/comments/create|reply`，使用网页域 XSRF Cookie；纯文本保留现有移动网页版路径。没有自动重放写请求。
- 发布失败保留图片和已上传 ID，重试不重复上传；切目标各自保存附件，切账号清理。选择器迟到的结果也校验原草稿身份。
- 表情选择与正文渲染优先使用下述在线目录；离线回退采用 `WeiboEmojis` 随包目录：178 个微博表情、73 个 Unicode Emoji、25 个其他表情（浪小花、哆啦 A 梦等），附最近使用入口（当前导航条目保存至多 28 个）。微博 / 其他表情按 One 1.1.6 随包资源及 `fx3` 表进行去重与别名映射，共 203 张本地图片、318 个正文代码 / 别名；随包资源作为离线回退，接收内容优先使用在线目录及已缓存包图片渲染，选择后插入原始表情代码或 Unicode。表情面板展开时清除文本焦点并隐藏输入法，切回键盘或点击编辑区恢复输入。
- @ 用户 sheet 默认展示关注列表，支持搜索昵称并插入 `@昵称 `；话题 sheet 默认展示热门词条，支持搜索和直接使用输入的话题，插入 `#话题#`。选择可替换光标前正在输入的 @ / # 片段；搜索使用防抖、取消和请求身份校验。
- 本次没有新增依赖；使用现有 Activity 1.13.0、Material 3 及 Coil。sheet 使用当前工程可用的 `rememberBottomSheetState`。

协议参考：[Android Photo picker](https://developer.android.com/training/data-storage/shared/photo-picker)、[weibo-cli 发布者提供的评论图片协议说明](https://pypi.org/project/weibo-cli/1.0.6/)。网页上传协议需要实机账号验证，不能把第三方客户端的实现记录当作微博官方服务保证。

## 博主与话题高亮、导航

正文 / 评论识别纯文本及 HTML 包装的 @博主、#话题#，使用主题强调色和站内点击回调；博主链接包含 UID 时优先传递该 UID。无 UID 的昵称按用户搜索结果精确匹配，不从关键词微博的首个作者猜测目标；未找到时显示错误。搜索页、话题页中的 @ 回调统一传向博主主页。

回复编辑区使用相同实体规则高亮 @昵称 和完整 #话题#。编辑器采用 Compose 1.12.0 已有的 `TextFieldState` / `OutputTransformation`，将已知本地及在线表情代码压缩为一个视觉占位，在文字排版对应位置绘制图片；发送、草稿及复制保留原始代码，Unicode Emoji 仍由系统字体绘制。框架负责视觉与原始偏移映射，绘制层随编辑器滚动并裁剪；未知代码保留文本，在线图片失败时在占位处显示代码。`InputTransformation` 把删除及选区替换扩展至整枚表情，长度限制不截断已知表情或 UTF-16 代理对。外部草稿同步识别自身回显，保留较新输入、光标及未变更时的输入法组合态。编辑区保留文本编辑手势；正文和评论中的实体链接负责点击导航。HTML 标题中的字符实体、单引号属性和昵称中的 Unicode 字符均有解析回归覆盖。

## 在线表情包

分组栏直接以可横向滚动的图标 tab 展示最近、微博、Unicode Emoji、在线分类与扩展包。`https://api.weibo.com/2/emotions.json?source=7501641714` 提供当前基础表情及分类；2026-10-23 实际只读核对返回 341 条、10 个分类。`https://api.weibo.cn/2/expression/get?type=0` 返回 123 个扩展包、`type=1` 返回 1 个热门包；热门 ZIP 包含 46 个表情，只是精选内容，并非完整基础目录。热门内容与基础目录按发送代码合并为一个“微博表情”tab，没有重复的热门入口。公开目录不保证收录全部历史表情，目录数量随服务端更新。

打开表情面板时由 `OnlineEmojiViewModel → EmojiRepository → OnlineEmojiSource / EmojiPackageStore` 获取目录并更新热门包；点击 tab 或在表情内容区左右滑动切换分组；使用现有 Foundation `HorizontalPager`，每个分组保留独立网格滚动位置，顶部 tab 跟随高亮并滚动至可见位置；刷新按钮位于横向 tab 列表末尾，随列表滚动。目录增删按分组 ID 恢复选择，切至扩展包并停稳后按需下载，直接在当前面板显示进度、内容及失败重试。移除了独立管理 sheet。已有缓存立即展示，在线目录成功后替代离线分组；Unicode 仍使用系统字体。tab 占用 36dp、内部图片 19dp、网格图片 26dp、工具栏图标 20dp；表情网格点击区域保留 48dp。网格默认不展示名称，使用现有 Material 3 `TooltipBox` / `PlainTooltip` 长按显示对应标签。沿用当前 Material 3 alpha27，无新增或升级依赖；按所用 API 局部 opt-in。

网络实现为 `WeiboEmojiApi`，不发送账号 Cookie 或签名。Android 存储 `AndroidEmojiPackageStore` 位于应用私有 `filesDir/emoji-packs`，基础分类元数据原子写入 `catalog.json`，图片使用应用统一 Coil 磁盘缓存，尚未加载过的在线图片不保证离线可用；ZIP 扩展包完整保存图片。应用启动只恢复缓存，不主动请求网络。刷新或下载失败保留已有内容，取消释放下载状态，支持同包重试。基础目录缓存写入失败时仍提交成功取得的在线目录，并继续获取扩展包目录；旧磁盘缓存由原子写入机制保留。下载或解包期间目录版本发生变化时不发布旧版本，持有同包下载互斥直到取得最新版本或失败，下载状态与互斥占用一并释放。
ZIP 按目录声明的版本验证，限制压缩大小、展开大小与文件数量，拒绝越界路径及无效图片；缓存写入新版本后原子替换当前清单。当前实现保留旧版本文件，不提供手动卸载入口。面板插入原始 `chs` 表情代码，正文 / 评论通过统一的只读图片表识别已安装包及别名；此表不存储账号信息，跨页面共享。部分历史表情代码是否继续由微博服务端转换，以实机发送结果为准。

本次针对性验证覆盖分类解析和去重、基础目录持久化与离线恢复、失败刷新保留目录及图片优先级、目录异常、下载去重、真实协程取消后的重试、离线恢复、坏包更新回退、ZIP 路径校验、生产依赖图，以及在线表情正文渲染。界面与真实账号发送仍由用户进行实机测试；未引入新依赖或声称支持 Desktop。
