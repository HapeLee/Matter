# 关注信息流中的未关注作者过滤

2026-11-04：继续使用现有网页端点，在 TimelineRepository 返回页面数据前过滤。

## 规则

- 普通关注时间线及特别关注、自建分组等关注流，移除外层作者明确为未关注的条目。优先使用 FollowRepository 已有的本会话关注状态；没有覆盖时使用响应的 `user.following`。
- 保留自己的微博。只检查外层发博者，已关注博主转发陌生人的原微博仍保留。
- `following` 缺失时保留，不将未知关系当作未关注，不增加逐个作者的资料请求。
- 悄悄关注、群微博和 V+ 分组不使用普通关注关系过滤，避免误删这些分组特有成员的内容。
- 规则不搜索微博正文关键词，也没有移植移动客户端的全部广告、推荐识别逻辑。热门流、搜索、正文页不受这次过滤影响。

因此这项修复过滤的是已明确识别的未关注作者，不能保证移除所有广告，或验证作者一定属于“特别关注”分组。若响应不下发关系字段，或需要严格校验分组成员，仍需实际响应样本及独立的成员关系来源。

## 分页、缓存与失败

WeiboApiService 优先读取顶层或 `data` 内的 `max_id_str` / `max_id`，未提供时使用原始响应末条微博 ID。原始页游标经 Repository、ViewModel 与缓存保存，不从过滤后的可见列表重新推导。明确的 `0` 游标表示结束。

过滤后空页或服务端空页仍有下一游标时继续读取；每次 Repository 调用最多读取 5 个原始页。达到上限返回可继续加载的空页，页面提供“继续加载”或列表末尾的“加载更多”。重复或循环游标作为失败处理，失败可重试，不提交中间页的游标。

刷新接续旧列表时保留旧列表底部的游标；刷新接续失败保留旧数据与游标。切组推进请求代次并取消旧任务，读取跨页期间校验账号 UID 与 Cookie；缓存写入绑定结果所属 UID。

缓存新增过滤前游标及版本。旧版缓存缺少游标，升级后失效并重新加载一次；新版缓存恢复时再次应用当前关注关系过滤。缓存仍最多保存前 150 条，裁剪时以实际保留内容的末项 ID 恢复翻页，并保留继续加载能力，避免跳过未保存的内容。

## 验证范围

单元测试覆盖明确未关注作者、自身、未知关系、转发、共享关注状态覆盖、特殊分组例外、原始游标、连续过滤页、请求上限、失败同页重试、循环游标、慢响应取消与账号切换、刷新与分页交错，以及缓存游标恢复与旧缓存失效。

当前只实现 Android 工程；没有新增 KMP target 或 Desktop 实现。模拟响应和 Robolectric 测试不等于已使用真实登录账号验证微博线上响应。
